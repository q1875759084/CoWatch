> 视角：QA 工程师（面试 / 可测试性视角）
> 范围：React 渲染进程 + Electron 主进程（TypeScript）
> 性质：纯分析，**不写测试代码、不装框架**，只给结构化建议与可抄示例片段

## 一、现状结论

| 维度 | 现状 |
|---|---|
| 自有单测文件 | **0 个**（`src/**/*.test.ts(x)`、`*.spec.ts(x)` 全部在 `node_modules`） |
| 测试框架 | **无**（devDependencies 仅含 webpack/babel/typescript/electron，无 jest/vitest） |
| `package.json` scripts | 仅 `dev/build/type-check/electron:*`，**无 `test`** |
| 类型检查 | 有 `tsc --noEmit`（`type-check` / `type-check:electron`），但**类型检查 ≠ 单测** |
| Electron 主进程 | 历史踩坑最重逻辑（录制参数构建、segment 排序、路径拼接）**完全无担保** |

**风险敞口一句话**：所有运行时分支、边界、错误路径、状态机合法性、数据转换正确性，目前只能靠人工 + 线上复现兜底。这正是面试最看重的「确定性逻辑」全部裸露在测网之外。

**纯函数 vs 强耦合副作用（已实测分类）**：

- ✅ 易测纯函数（建议优先抽出来单测）：`hlsSegment.ts` 全套、`validateVideo.ts` 的 `checkMoovBeforeMdat`、`throttle.ts`、`token.ts`（轻量 mock）、`electron/.../shared.ts` 的 `buildExeArgs`/`makeDefaultProfiles`/`getSegmentKeys`/`sanitizeApiOrigin`、`persistence` 的 `parseSegmentIndex` 与排序逻辑（待提取）、`upload/throttle.ts` 的 `calculateUploadTimeout`、`recorder.ts` 的 `RESOLUTION_MAP`。
- ⚠️ 强耦合副作用（需 mock / 集成测，不要硬塞单测）：`upload/index.ts` 的 `enqueueMissingFiles`/`doUpload`（fs/net/p-retry）、`request.ts` 拦截器（`window.location`/axios 实例/electronBridge）、React 组件（`Recorder`、`WindowPicker`、`VideoList`、`VideoPlayer`）、`persistence` 的 `persistRecording`/`listPendingRecordings`/`resumeUpload`（fs+electron）。

## 二、面试视角为何重要：5 大确定性关注点 × CoWatch 真实风险

面试最看重 **纯函数确定性、边界条件、错误路径、状态机合法性、数据转换正确性**。对应 CoWatch 的真实风险（部分已是「用单测本可提前拦住」的历史踩坑）：

1. **纯函数确定性 → HLS 段名排序错位 / seek 乱跳**
   - `persistence/index.ts:55` `parseSegmentIndex` 用正则 `/^seg(\d+)/`，**匹配失败返回 0**。一旦个别切片文件名不含数字（如临时 `seg_opt.ts`、异常命名），多个文件 index 同为 0，`segments.sort((a,b)=>a.index-b.index)`（`:111`）排序塌缩为不稳定顺序 → 播放端按 manifest 顺序拼接 → **seek 乱跳**。这是典型「边界值 + 确定性」漏洞，单测 2 行即可拦住。
2. **边界条件 → 码率 / 体积校验边界**
   - `validateVideo.ts`：`basic` 计划要求「moov 在 mdat 前 + 平均码率 ≤ 8Mbps」（`MAX_BITRATE_MBPS=8`）；`vip:pro` 跳过校验**仅限文件 ≤ 3GB**（`MAX_FILE_SIZE_BYTES=3GB`）。边界值「恰好 8.0001Mbps」「恰好 3GB+1 字节」「duration=0 导致除零」均未被任何测试守护。
3. **错误路径 → 相对路径落 CWD**
   - `shared.ts` 的 `buildExeArgs` 用 `path.join(userDataDir, RECORD_BASE_DIR, sessionId, 'segments')` 拼输出目录。若 `userDataDir` 在某些上下文为空/undefined，`path.join` 会退化为**相对路径落到进程 CWD**（历史「相对路径落 CWD」踩坑）。单测断言「返回值必须为绝对路径」即可锁死。
4. **状态机合法性 → RecorderState 非法转换**
   - `recorder.ts:36` 定义 `idle→detecting→ready→recording→finishing→idle`，且 `recording→ready`（异常中止）。当前状态流转**散落在组件与 IPC 回调里，没有集中校验函数**。面试常考「非法转换表」，目前若某处误调 `updateState('idle')` 从 `recording` 直接跳回，无单测可发现。
5. **数据转换正确性 → token 双存储 / 401 并发刷新队列**
   - `token.ts` 内存+localStorage 双存储，页面刷新恢复逻辑；`request.ts:29-108` 的 401 无感刷新全局互斥锁 + `pendingQueue` 并发重放。这两处是「数据转换 + 并发正确性」高频考点，目前零测试。

## 三、单测优先级清单（P0 / P1 / P2）

> 标注【纯】= 纯函数易测；【mock】= 需轻量 mock；【集成】= 组件/集成测。

### 🔴 P0：纯函数 + 高风险 + 历史踩坑

#### P0-1 `src/utils/hlsSegment.ts`【纯】
- **建议测函数**：`isHlsSegment` / `stripSignature` / `parseSegmentMeta` / `extractUserId`
- **关键用例（边界 + 错误路径）**：
  - `parseSegmentMeta`：**新格式** `/api/rooms/{roomId}/videos/{videoId}/segments/{segmentName}.ts`、**旧格式** `/cowatch/...`、**`/uploads/cowatch/...`** 三种各 1 例 + 非法 URL（非 .ts、路径不含 room/video）→ 断言返回 `null`。
  - `stripSignature`：含 `sign`/`uid`/`q-sign-algorithm`/`q-sign-time`/`q-sign-key` 等系列参数 → 全部剥离，其余参数保留；空 query、无签名参数各 1 例。
  - `isHlsSegment`：`/cowatch/xxx.ts` 与 `/segments/xxx.ts` 命中；`.m3u8`/`.mp4`/非 .ts → `false`。
  - `extractUserId`：有 `uid=abc` → `'abc'`；缺 `uid` → `'anonymous'`。
- **为何面试加分**：多格式解析 + null 错误路径 + query 剥离的纯确定性，是「字符串/URL 解析」经典题，覆盖率高、无依赖、可秒级跑完。

#### P0-2 `src/utils/validateVideo.ts` 的 `checkMoovBeforeMdat`【纯】
- **建议测函数**：`checkMoovBeforeMdat(buffer: ArrayBuffer)`
- **关键用例**：
  - 构造 mock `ArrayBuffer`：`ftyp → moov → mdat`（moov 在前）→ `true`。
  - 构造 `ftyp → mdat → moov`（moov 在后）→ `false`。
  - 无 moov / 无 mdat → `false`；空 buffer / 仅 ftyp → `false`（边界）。
  - 多个 box、嵌套 size 边界（box size = 剩余全部）读取不越界。
- **为何面试加分**：「扫描字节流找结构顺序」是二进制解析硬核题，直接对应历史「moov 不在前导致首帧黑屏/无法流式」踩坑。

#### P0-3 `src/types/recorder.ts` 状态机 + `RESOLUTION_MAP`【纯】
- **建议测**：将状态流转提取为纯函数 `canTransition(from, to): boolean`（当前散落，建议新增 `src/utils/recorderState.ts`）；`RESOLUTION_MAP` 映射。
- **关键用例**：
  - 合法：`idle→detecting`、`detecting→ready`、`ready→recording`、`recording→finishing`、`finishing→idle`、`recording→ready`(abort)。
  - 非法（返回 false）：`idle→recording`、`detecting→recording`、`recording→idle` 直跳、`finishing→recording`。
  - `RESOLUTION_MAP['720p']` → `{1280,720}`；`['900p']` → `{1600,900}`；未知 key → `undefined`（边界）。
- **为何面试加分**：状态机合法性表是「有限状态机」标准面试题，且直接锁死历史「异常中止状态错乱」。

#### P0-4 `electron/handlers/recorder/shared.ts` 录制参数构建 / segment key / 路径拼接【纯】
- **建议测函数**：`buildExeArgs` / `makeDefaultProfiles` / `getSegmentKeys` / `sanitizeApiOrigin`
- **关键用例**：
  - `buildExeArgs`：`userDataDir` 正常 → 输出含 `-segment_time 6`(HLS_SEGMENT_DURATION)、`-rc_mode`(由 rcMode 映射)、`-vf scale={w}:{h}`(由 resolution 映射)、`-f hls`；**`userDataDir=''`/`undefined` → 断言输出为绝对路径、不以 `./` 开头**（锁死「相对路径落 CWD」）。
  - `makeDefaultProfiles`：返回 720p/900p 两档，每段 `segment_time=6`、带 `-gap`；字段结构完整。
  - `getSegmentKeys(dir, objectDir, sessionId, roomId)`：用 mock `fs`(vi.mock) 返回 `[seg000.ts, seg001.ts]` → 断言生成 `cowatch/{roomId}/recordings/{sessionId}/seg000.ts` 顺序正确、无重复。
  - `sanitizeApiOrigin`：带尾部 `/`、无协议、`http://x/` → 归一化；非法 → 兜底默认。
- **为何面试加分**：exe 参数拼接 / 路径拼接的经典「绝对路径 vs 相对路径」「参数映射正确」题，且是 Electron 主进程踩坑最重区。

#### P0-5 `electron/handlers/recorder/persistence/index.ts` 段名解析与排序【纯，待提取】
- **建议测函数**：将 `parseSegmentIndex`(`:55`) 与 `segments.sort((a,b)=>a.index-b.index)`(`:111`) 提取为纯函数 `parseSegmentIndex(name):number` 与 `sortSegmentsByIndex(arr)`；objectKey 构造 `cowatch/${roomId}/recordings/${sessionId}/${fileName}`(`:104`) 提取为 `buildObjectKey(...)`。

## 四、测试框架与落地建议

**推荐 Vitest**（而非 Jest）：
- 与现有 TS/Webpack/Babel 体系零摩擦，`vite` 配置轻量，无需额外 transform。
- 开箱即用：`vi.useFakeTimers()`（throttle/Date 类）、`vi.mock()`（axios/localStorage/electron）、`environment: 'jsdom'`（DOM/组件）、`environment: 'node'`（Electron 主进程逻辑）。
- Electron 主进程纯逻辑可用 `vi.mock('electron')` 隔离 `app`/`net`/`fs`，或用 `@electron-toolkit/utils` 的 `is` 判定。
- 复用现有 `tsconfig` 路径别名 `@/*`（需在 vitest 配置里配 `resolve.alias` 或 `vite-tsconfig-paths`）。

**最小落地步骤**：
1. `npm i -D vitest @types/node`（按需 `jsdom` / `vite-tsconfig-paths`）。
2. 仓库根新增 `vitest.config.ts`：配 `test.environment` 默认 `node`，`include: ['src/**/*.test.ts','electron/**/*.test.ts']`，别名 `@` → `src`。
3. `package.json` 增 `"test": "vitest run"` 与 `"test:watch": "vitest"`。
4. 写第一个 P0 用例：`src/utils/hlsSegment.test.ts`（见第五节），`npm test` 跑通即建立信心与基线。
5. 后续按 P0→P1→P2 推进；Electron 主进程文件用 `// @vitest-environment node` 注释隔离。

### 片段 2：`checkMoovBeforeMdat` 构造 ArrayBuffer（P0-2）
```ts
// 工具：造一个 [size][type] 字节流的 ArrayBuffer
function makeMp4(boxes: Array<[string, number?]>): ArrayBuffer {
  // 每个 box: 4 字节大端 size + 4 字节 ascii type (+ 可选填充)
  let total = 0;
  const parts = boxes.map(([type, extra = 0]) => {
    const size = 8 + extra; total += size; return { type, size };
  });
  const buf = new ArrayBuffer(total);
  const dv = new DataView(buf);
  let off = 0;
  for (const { type, size } of parts) {
    dv.setUint32(off, size);                 // box size
    for (let i = 0; i < 4; i++) dv.setUint8(off + 4 + i, type.charCodeAt(i));
    off += size;
  }
  return buf;
}

it('moov 在 mdat 前 → true', () => {
  const buf = makeMp4([['ftyp', 4], ['moov', 8], ['mdat', 8]]);
  expect(checkMoovBeforeMdat(buf)).toBe(true);
});

it('moov 在 mdat 后 → false', () => {
  const buf = makeMp4([['ftyp', 4], ['mdat', 8], ['moov', 8]]);
  expect(checkMoovBeforeMdat(buf)).toBe(false);
});

it('缺 moov / 空 buffer → false（边界）', () => {
  expect(checkMoovBeforeMdat(makeMp4([['ftyp', 4], ['mdat', 8]]))).toBe(false);
  expect(checkMoovBeforeMdat(new ArrayBuffer(0))).toBe(false);
});
```

### 片段 3：`RecorderState` 非法转换表（P0-3，建议提取 `canTransition`）
```ts
// src/utils/recorderState.ts（新增纯函数）
export function canTransition(from: RecorderState, to: RecorderState): boolean {
  const map: Record<RecorderState, RecorderState[]> = {
    idle:       ['detecting'],
    detecting:  ['ready'],
    ready:      ['recording', 'idle'],
    recording:  ['finishing', 'ready'], // ready = 异常中止
    finishing:  ['idle'],
  };
  return map[from]?.includes(to) ?? false;
}

// recorderState.test.ts（节选）
const LEGAL: [RecorderState, RecorderState][] = [
  ['idle', 'detecting'], ['detecting', 'ready'], ['ready', 'recording'],
  ['recording', 'finishing'], ['finishing', 'idle'], ['recording', 'ready'],
];
const ILLEGAL: [RecorderState, RecorderState][] = [
  ['idle', 'recording'], ['detecting', 'recording'], ['recording', 'idle'],
  ['finishing', 'recording'], ['ready', 'detecting'],
];
it.each(LEGAL)('合法 %s→%s', (f, t) => expect(canTransition(f, t)).toBe(true));
it.each(ILLEGAL)('非法 %s→%s', (f, t) => expect(canTransition(f, t)).toBe(false));
```
