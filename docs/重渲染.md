# State 下沉：避免无效重渲染

## 旧版：state 提升到父组件

```jsx
// ❌ 父组件持有 B 的 UI state
function Parent() {
  const [collapsed, setCollapsed] = useState(false);

  return (
    <>
      <ChildA />
      <ChildB collapsed={collapsed} onToggle={() => setCollapsed(v => !v)} />
    </>
  );
}

function ChildA() {
  console.log('重渲染');  // 每次 collapsed 变化都会打印

  useEffect(() => {
    console.log(111);     // 仅在 deps 变化时才打印，不随 render 执行
  }, []);                 // deps=[] 所以只打印一次，但函数体本身每次 render 都重新创建

  return <div>A 的内容</div>;
}

function ChildB({ collapsed, onToggle }) {
  return (
    <button onClick={onToggle}>
      {collapsed ? '展开' : '折叠'}
    </button>
  );
}
```

**执行流程：**

1. 点击 B 的按钮 → `onToggle` 调用 `setCollapsed`
2. `collapsed` 变化 → **Parent re-render**
3. Parent re-render → **ChildA、ChildB 函数体全部重新执行**
4. `ChildA` 打印 `'重渲染'` ← B 的行为殃及了无关的 A
5. `ChildA` 的 `useEffect` **不执行**：deps `[]` 未变化，React 跳过

> `useEffect` 的回调执行与否取决于 **deps 是否变化**，与组件函数是否 re-render 无关。
> 函数体每次 render 都重新执行，但 `useEffect` 内部的回调由 React 在 commit 阶段按 deps 决策。

## 新版：state 下沉到 ChildB 内部

```jsx
// ✅ B 自己的 UI state 内聚在 B 内部
function Parent() {
  return (
    <>
      <ChildA />
      <ChildB />    {/* Parent 不再持有 collapsed */}
    </>
  );
}

function ChildA() {
  console.log('重渲染');  // 不再打印 ← B 的行为不影响 A

  useEffect(() => {
    console.log(111);     // 仅初始化执行一次
  }, []);

  return <div>A 的内容</div>;
}

function ChildB() {
  const [collapsed, setCollapsed] = useState(false);  // state 内聚

  return (
    <button onClick={() => setCollapsed(v => !v)}>
      {collapsed ? '展开' : '折叠'}
    </button>
  );
}
```

**执行流程：**

1. 点击 B 的按钮 → `setCollapsed` 调用
2. `collapsed` 变化 → **仅 ChildB re-render**
3. Parent 不 re-render → **ChildA 完全不执行**
4. `ChildA` 的 `'重渲染'` 不打印 ✅
5. `ChildA` 的 `useEffect` 不执行 ✅（deps 未变，且组件根本没 re-render）

## 备选方案：React.memo 阻断父到子的传播

当 state **无法下沉**（确实需要在父组件持有），可以用 `React.memo` 让子组件跳过 re-render。

```jsx
// state 必须留在 Parent（比如同时被多个子组件读取）
function Parent() {
  const [collapsed, setCollapsed] = useState(false);

  return (
    <>
      <ChildA />    {/* 用 memo 包裹后，props 不变则跳过 */}
      <ChildB collapsed={collapsed} onToggle={() => setCollapsed(v => !v)} />
    </>
  );
}

// React.memo：对 props 做浅比较，props 未变则跳过 render
const ChildA = React.memo(function ChildA() {
  console.log('重渲染');  // 不再打印，因为 ChildA 没有 props，浅比较永远相等

  useEffect(() => {
    console.log(111);
  }, []);

  return <div>A 的内容</div>;
});
```

**执行流程：**

1. 点击 B → `setCollapsed` → Parent re-render
2. React 尝试渲染 `ChildA`，发现它被 `memo` 包裹
3. 对比前后 props：`{}` vs `{}` → 浅比较相等 → **跳过 ChildA 的 render**
4. `'重渲染'` 不打印 ✅，`useEffect` 不执行 ✅

**memo 的代价与陷阱：**

```jsx
// ❌ 陷阱：每次 render 都产生新的函数引用，memo 失效
<ChildA onAction={() => doSomething()} />
//       ↑ 每次 Parent render 都是新函数，浅比较不相等，memo 无效

// ✅ 配合 useCallback / useMemoizedFn 稳定引用
const handleAction = useMemoizedFn(() => doSomething());
<ChildA onAction={handleAction} />
```

> **memo vs 状态下沉的取舍**：
> - 状态下沉是**根治**：Parent 根本不 re-render，无需比较
> - React.memo 是**拦截**：Parent 仍然 re-render，只是子组件跳过；memo 本身有浅比较的开销
> - 优先选择状态下沉；只有 state 确实需要在父组件时才考虑 memo

## 核心规则

| 问题 | 原因 | 解法 |
|------|------|------|
| 子组件 B 的 state 导致无关兄弟 A 重渲染 | state 定义在共同父组件，父 re-render 带动全部子节点 | **首选**：state 下沉到 B 内部；**次选**：React.memo 包裹 A |
| memo 包裹后仍然重渲染 | props 中有每次 render 新建的对象/函数引用 | 配合 `useCallback` / `useMemoizedFn` 稳定引用 |
| useEffect 回调被意外执行 | 误以为函数体执行 = effect 执行 | effect 只看 deps，与 render 次数无关 |

> **React render 流程**：state/props 变化 → 组件函数重新执行（render）→ React diff 决定是否更新 DOM → commit 阶段执行 effect。
> render 和 effect 是两个独立阶段，不要混淆。
