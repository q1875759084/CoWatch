# 窗口录屏模式 - 对象窗口关闭行为分析

## 一、当前行为（发生了什么）

### 核心链路

```
用户关闭被录制窗口
  → gfxcapture 的 window_title 失去匹配目标
    → ffmpeg 视频流停止产生新帧
      → ffmpeg 进程异常退出（触发 close event）
        → isUserStopped = false → 判定为 crash
          → handleFfmpegCrash() 用相同 displayTitle 重启 ffmpeg
            → 重启后 gfxcapture 仍找不到窗口 → 再次 crash
              → 循环 3 次（MAX_CRASH_RESTARTS = 3）
                → 超过上限，push recorder:error
                  → UI 弹窗"ffmpeg 持续崩溃，录制已终止"
```

### 关键代码位置

| 文件 | 行号 | 逻辑 |
|------|------|------|
| `electron/handlers/recorder.ts` | 791-801 | gfxcapture 通过 window_title 正则匹配窗口 |
| `electron/handlers/recorder.ts` | 1015-1023 | close 事件处理，非正常退出触发 crash 恢复 |
| `electron/handlers/recorder.ts` | 961-1010 | handleFfmpegCrash() 用相同 displayTitle 重启 |
| `electron/handlers/recorder.ts` | 965-970 | 超过 MAX_CRASH_RESTARTS(3) 放弃，推送 error |

### 具体问题

1. **无主动窗口状态检测**：代码中没有任何定时器或事件监听被录制窗口是否存在
2. **误判为 crash 并无意义重启**：窗口关闭导致的 ffmpeg 退出被当作普通崩溃处理，用相同标题重启 3 次注定失败
3. **无优雅停止流程**：超过重启上限后直接 push error，不走 `stop()` 流程 → 尾片丢失、`/recording/finish` 接口未调用
4. **UI 体验差**：用户看到的是"ffmpeg 持续崩溃"，而非"被录制窗口已关闭"

### 衍生问题：CoWatch 主窗口关闭

`electron/main.ts` 第 149-151 行：
```typescript
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit();
});
```
用户关闭 CoWatch 窗口时直接 `app.quit()`，**没有 before-quit 钩子调用 `stop()` 做优雅停止**，ffmpeg 子进程被 OS 强杀，尾片丢失，finish 接口未调用。

## 二、解决方案

### 方案 A：主动窗口状态轮询（推荐）

在 `start()` 中增加一个定时器，每 2 秒通过 `desktopCapturer.getSources` 枚举窗口，检查 `displayTitle` 是否仍存在。

```typescript
// recorder.ts 新增
let windowCheckTimer: NodeJS.Timeout | null = null;

function startWindowMonitor(displayTitle: string): void {
  windowCheckTimer = setInterval(async () => {
    if (isUserStopped || !ffmpegProcess) return;
    try {
      const sources = await desktopCapturer.getSources({
        types: ['window'],
        thumbnailSize: { width: 1, height: 1 }, // 最小缩略图，减少开销
      });
      const exists = sources.some(s => s.name === displayTitle);
      if (!exists) {
        console.warn(`[recorder] 被录制窗口 "${displayTitle}" 已关闭，优雅停止录制`);
        stopWindowMonitor();
        // 通知 UI
        for (const win of BrowserWindow.getAllWindows()) {
          win.webContents.send('recorder:window-closed', displayTitle);
        }
        // 优雅停止（补传尾片 + finish 接口）
        void stop();
      }
    } catch (e) {
      // 枚举失败不中断录制，下次再检查
    }
  }, 2000);
}

function stopWindowMonitor(): void {
  if (windowCheckTimer) {
    clearInterval(windowCheckTimer);
    windowCheckTimer = null;
  }
}
```

**优点**：响应快（2s 内）、优雅停止不丢尾片、不触发无意义重启
**缺点**：增加一个定时器，desktopCapturer 有轻微开销
**改动量**：约 40 行，改动集中在 `recorder.ts`

### 方案 B：ffmpeg 错误码 + stderr 智能识别（备选）

在 `attachFfmpegHandlers` 的 close 回调中，检查 exit code 和 stderr 输出，识别"窗口不存在"场景，跳过重启直接走 `stop()`。

```typescript
let ffmpegStderrBuffer = '';

function attachFfmpegHandlers(displayTitle: string): void {
  ffmpegStderrBuffer = '';
  ffmpegProcess?.stderr?.on('data', (chunk: Buffer) => {
    ffmpegStderrBuffer += chunk.toString();
  });

  ffmpegProcess?.on('close', (code) => {
    if (isUserStopped) return;

    // 检查是否是窗口关闭导致的退出
    const windowNotFound =
      ffmpegStderrBuffer.includes('Could not find window') ||
      ffmpegStderrBuffer.includes('window_title') && ffmpegStderrBuffer.includes('error');

    if (windowNotFound) {
      console.warn(`[recorder] 被录制窗口已关闭，优雅停止`);
      for (const win of BrowserWindow.getAllWindows()) {
        win.webContents.send('recorder:window-closed', displayTitle);
      }
      void stop();
      return;
    }

    // 其他原因的 crash，走原有重启逻辑
    void handleFfmpegCrash(displayTitle);
  });
}
```

**优点**：改动最小、无额外定时器
**缺点**：依赖 ffmpeg/gfxcapture 的 stderr 输出格式，版本升级可能失效；exit code 不稳定
**改动量**：约 20 行

### 方案 C：Windows 原生 API 事件监听（长期最优）

通过 `SetWinEventHook` 监听 `EVENT_OBJECT_DESTROY`，在窗口销毁时精准触发停止。

需要 native addon（如 `node-ffi-napi` 或自定义 N-API 模块）或通过 PowerShell 桥接。

```typescript
// 伪代码 - 需要 native 模块支持
import { setWinEventHook, EVENT_OBJECT_DESTROY } from 'native-win-events';

function startWindowHook(hwnd: number, displayTitle: string): void {
  const hook = setWinEventHook(
    EVENT_OBJECT_DESTROY, EVENT_OBJECT_DESTROY,
    (event, windowHwnd) => {
      if (windowHwnd === hwnd) {
        console.warn(`[recorder] 窗口 "${displayTitle}" 已销毁`);
        void stop();
      }
    }
  );
}
```

**优点**：毫秒级响应、零轮询开销、事件驱动精准
**缺点**：需要 native addon，增加构建复杂度，跨平台需分别实现
**改动量**：较大，需引入 native 依赖

## 三、推荐实施路径

**短期**：方案 A（主动轮询），改动小、见效快、风险低

**中期**：方案 A + 方案 B 组合，轮询做主动检测，stderr 识别做被动兜底

**长期**：方案 C（原生 API），作为性能优化升级

### 额外建议：修复 CoWatch 主窗口关闭问题

在 `electron/main.ts` 中增加 `before-quit` 钩子：

```typescript
app.on('before-quit', async (event) => {
  // 如果正在录制，先优雅停止
  if (recorder.isRecording()) {
    event.preventDefault();
    await recorder.stop();
    app.quit();
  }
});
```
