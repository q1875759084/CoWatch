## 记事本 file 模式真机复测：mux 失败 + 进程不退出（运行时 bug 修复）
- **现象**：`--mux-target file` 跑记事本，ffmpeg 立刻 `[hls] first pts and dts value must be set` + `Error submitting a packet` + `Conversion failed!`；之后 capture-src 不退出、空转到需强杀；cpu_pct 100、capture_fps 最终 0（静态记事本 WGC 本身极少出帧，0 属预期）。
- **根因 A（致命，mux 无输出）**：`output_target.cpp` FileTarget ffmpeg 命令 `T7` 重构时"去掉 `-r` 谎言、靠 VUI 取 PTS"是**错误认知**——裸 H.264/H.265 Annex-B 码流无逐帧 PTS/DTS（SPS VUI 仅时序提示，ffmpeg h264/hevc demuxer 不会据此生成 packet 时间戳），HLS/mpegts muxer 要求首包有 PTS/DTS → 直接 Conversion failed。`+genpts` 在无 DTS 时也无米之炊。
- **根因 B（进程空转）**：ffmpeg 崩了 `pipe_output.cpp:31` 的 `writeFd` 仅 `break` 丢包不置 `g_quit`，capture-src 继续空转；`ConsoleCtrlHandler` 虽置 g_quit，但 ffmpeg 先死后进程已无产出，用户体感"退不掉"。
- **修复（本环境无 TeamCreate，Agent 派发需先建团队故不可用，主理人直接落地）**：
  1. `output_target.cpp` FileTarget ffmpeg 命令补 `-r <fps>`（`-i -` 前，`cfg.fps` 来自 OutputTargetConfig）：`-y -fflags +genpts -f <h264|hevc> -r <fps> -i -`；更正 4 处"去 -r 谎言"误导注释（.h 顶部块 + :15 + :40，.cpp 顶部块 + 命令处）。
  2. 新增 mux 进程监控：`FileTarget` 加 `static muxMonitorThread`（WaitForSingleObject 子进程；非 0 退出且非主动 stop → 置 `m_muxDied`）；`OutputTarget` 基类加虚 `muxDied()`（默认 false），FileTarget override；`init` 启监控线程，`stop` 置 `m_stopping` 抑制误报并 join 线程；`<atomic>` 已加。
  3. `main.cpp` 主循环消费 `if (mux->muxDied()) { emitError(3,...); g_quit=true; }` → ffmpeg 异常退出时 capture-src 自检优雅退出（不再需强杀）。
- **未动**：阻塞锁 tryLockPacket / gate=bf+1 / tryConsumeFrame / m_textureWritten / m_inFlight；Push/Null 模式行为（仅基类加默认 muxDied=false）。

## 用户灵魂拷问：OBS 有 HLS 输出，为何 capture-src 还会出"参数错 + 退不掉"？
- **用户质疑（2026-07-19 午后）**：之前提到 OBS 有 HLS 结构的输出（只是走远程上传非落本地），那为何 capture-src 还会出 `-r` 时间戳错 + ffmpeg 死后不退？
- **主理人读本地 OBS 源码核实，结论：用户的直觉完全正确——两个 bug 都是 capture-src 对 OBS mux 架构的偏离所致，我之前的"补 -r + 监控子进程"是给偏离打补丁，未除根**。
- **OBS HLS mux 架构（两条路径都显式带戳，从不让 ffmpeg demuxer 猜）**：
  - 旧路径 `obs-ffmpeg-output.c`：内联 libavformat。`data->vframe->pts = data->total_frames;`（:681 帧计数器）→ `packet->pts/dts = rescale_ts(...)`（:701-702）→ `av_interleaved_write_frame`（:889）进程内 mux。
  - 新路径 `obs-ffmpeg-hls-mux.c` → 起独立 `obs-ffmpeg-mux` 子进程（FFMPEG_MUX "obs-ffmpeg-mux.exe"，obs-ffmpeg-mux.c:114）：主进程 `ffmpeg_hls_mux_data()` 收 `encoder_packet`（带 pts/dts/timebase）→ `ts_offset_update` 跟踪（`obs-ffmpeg-mux.c:349-362`）→ 序列化 `ffm_packet_info{pts,dts,timebase,...}` 写管道；子进程 `ffmpeg-mux.c:1086-1087` `pkt->pts/dts = rescale_ts(..., info->pts/info->dts, ...)` **显式重建戳**再 mux。
  - **关键**：无论哪条路径，OBS 都是"自己把 PTS/DTS 放到 packet 上"（进程内或带戳管道协议），**从不**把裸 Annex-B 喂给 `ffmpeg -f h264 -i -` 让 demuxer 去发明时间戳。
- **capture-src 的偏离（mux 部位的手搓）**：直接 spawn 外部 `ffmpeg.exe`，把 NVENC 出的**裸 Annex-B 字节**灌 stdin（`-f h264 -i -`），**丢弃了所有时间戳信息**。
  - Bug A 根：裸流无逐帧 PTS/DTS → muxer 报 `first pts and dts value must be set`。T7"去 -r 靠 VUI"假设错（ffmpeg 裸 demuxer 不据 VUI 生成 pkt 戳），`+genpts` 无 DTS 也无用 → Conversion failed。补 `-r` 让 ffmpeg 按帧计数合成戳，**功能等价于 OBS 的 `total_frames` 兜底，但 OBS 是"自己 stamp 在 packet 上"，我们是"逼 demuxer 猜"**。
  - Bug B 根：OBS 的 mux 子进程生命周期由 `obs_output_stop`→`ffmpeg_mux_stop` 主动 flush/等待收尾、输出 stop 序列驱动；capture-src 把子进程当黑盒 spawn 后**不监控**，ffmpeg 一死主循环继续空转。OBS 无此问题因为"子进程生死归 OBS 输出生命周期管"。
- **与铁律呼应**：working_memory 铁律"缺依赖/DLL 就补齐依赖（vendor libobs / 链 libavformat）而非手搓"——capture-src 的 mux 部位正是一处手搓偏离：没链 libavformat / 没 vendor `obs-ffmpeg-mux`，改成裸 pipe 给外部 ffmpeg。
- **两条收口路线（待用户拍板，主理人不擅自重构）**：
  - (A) **保当前 raw-pipe 方案**：`-r` + 子进程监控已能跑通，简单、不引入 DLL 依赖；代价=偏离 OBS、依赖 ffmpeg CLI 行为、是补丁非除根。
  - (B) **忠实移植 OBS mux**：链 libavformat（或 vendor `obs-ffmpeg-mux` helper），自己从 NVENC 帧序号/时基 stamp `pkt->pts/dts` 再 mux；两 bug 类从根消除、完全对齐 OBS；代价=带 ffmpeg DLL（avformat/avcodec/avutil 等）或编译进 helper、代码量更大、需把每帧 pts 透传到 mux 层。
- **主理人建议**：当前 A 已可用，先真机复验跑通验证清单；若后续要"零偏离 / 更稳"，再走 B。是否做 B 由用户决定（涉及 DLL 发布策略）。
- **B 方案改动量评估（用户问"B 需要多大改动"）**：中等、边界清晰、非重写。
  - 外部依赖成本**低**：CMakeLists 早已 `FFMPEG_ROOT` 必填且链了 avcodec/avutil；B 只是**多链 avformat.lib（+swresample）**、部署时随包多带 avformat/avcodec/avutil 几个 DLL——无需新装工具链。
  - 编码核心/锁模型/Push/Null **完全不动**。
  - 具体改动：① `EncodedPacket` 加 `uint64_t pts`（1 行）；② `nvenc_encoder.cpp` submitFrame 存 frameIndex/bitstreamIndex→tryLockPacket 回填 pts（~10 行，frameIndex 本就传入）；③ `main.cpp` 两处 `pipe.writeVideoPacket(pkt.data)`→`mux->writePacket(pkt)`（~4 行）；④ `PipeOutput` 签名透传 pkt（~3 行，Push/Null 忽略 pts）；⑤ `OutputTarget` 基类加虚 `writePacket(const EncodedPacket&)`，FileTarget 改进程内 mux；⑥ **新增 hls_mux.h/.cpp（核心，~250-300 行）**：照搬 OBS `obs-ffmpeg-output.c` 的 mux 段（`avformat_alloc_output_context2("hls")`→建 video stream+extradata→每包 `av_interleaved_write_frame` 带 pts/dts）；⑦ `FileTarget` 删 spawn/monitor/stderr 泵（删~120 行，加~120 行）；⑧ CMakeLists 链 avformat + 加 hls_mux.cpp 源（~10 行）。
