# 2026-07-12 CoWatch 工作日志

## build.ps1 构建脚本修复（方案2a C++ exe）
- 用户真机 build 时 `build.ps1` 报大量 PowerShell 语法错误（中文乱码破坏字符串结构）。
- 根因：`build.ps1` 为 UTF-8 **无 BOM**，PowerShell 5.1（VS Developer Command Prompt 配套的 powershell.exe）默认按系统 GBK 代码页读 .ps1，UTF-8 多字节中文被误读，部分字节撞上引号/转义字符。
- 修复：给 `build.ps1` 加 **UTF-8 BOM**（`file` 确认 `UTF-8 (with BOM)`）。
- 顺带改两处鲁棒性：① 去掉第36行强制 `Assert-Command ninja`，改为 ninja 可选；② cmake 生成器自动选择（有 ninja 用 Ninja，否则回退 `Visual Studio 17 2022`）。
- 经验（可复用）：Windows 下用 PowerShell 5.1 跑的 `.ps1` 脚本，**必须带 UTF-8 BOM 或全程 ASCII**，否则中文必乱码。VS Developer Command Prompt 调起的是 PS5.1（默认 ANSI），不是 pwsh7。

- `$env:FFMPEG_ROOT` 需指向 **FFmpeg 开发库（含 lib/avcodec.lib、lib/avutil.lib、include/）**，非仅 ffmpeg.exe。Windows 上需自行编译或从第三方拿 dev 包（BtbN/gyan.dev 的 dev 版），否则 cmake 配置会 throw。

## 架构师最终结论（FFmpeg 构建依赖精确清单）
- 链接范围锁定：exe 仅链 `avcodec.lib` + `avutil.lib` + `nvEncodeAPI.lib`（NVENC SDK，非 ffmpeg），不链 libavformat/device/filter/swscale/swresample。
- 具体预编译包推荐（修正 BtbN 命名）：
  - BtbN 没有文件名带 "dev" 的独立包。正确做法是下载 **BtbN `-shared` 包**（如 `ffmpeg-n8.1-latest-win64-lgpl-shared-8.1.zip`），它同时包含开发文件（include/ + lib/）和运行时 DLL（bin/），等效于 dev+shared 二合一。
  - 红框中**不带 `-shared-` 的静态包**（如 `ffmpeg-n8.1-latest-win64-lgpl-8.1.zip`）多为静态 `.a` 库，不适合 MSVC 动态链接，不推荐。
  - BtbN 是 MinGW 构建；解压后必须检查 `lib/` 下是 `avcodec.lib` / `avutil.lib`（MSVC 导入库）还是 `avcodec.dll.a` / `avutil.dll.a`（MinGW 导入库）。若是 `.dll.a`，可能需要转换成 `.lib` 或调整 CMakeLists。
  - 备选 gyan.dev：`ffmpeg-release-full-shared.7z` 是明确 MSVC 构建的 shared+dev 包（含 include/lib/bin/dll），但它是 **GPL**；若需 LGPL，BtbN `-lgpl-shared` 更合适。
- **/MD 一致性是铁律**：项目 CMake 锁 MultiThreadedDLL(/MD)；BtbN/gyan 官方包即 /MD，误用 /MT 包会 LNK2038。有配套 bin/*.dll 的导入库即动态(/MD)库。
- FFMPEG_ROOT 指向 dev 包根（直接含 include/ 与 lib/）；shared 的 DLL 复制到 electron/bin/（与 exe 同目录）。
- NVENC SDK 是独立第三方依赖（非 ffmpeg）：NVIDIA Video Codec SDK 的 nvEncodeAPI.h + Lib/x64/nvEncodeAPI.lib，配 NVENC_SDK_ROOT；运行时靠 NVIDIA 驱动。
- 不从 GitHub 源码编译 ffmpeg：源码库只有 C 源码无 .lib，自编译耗时易缺配置。
- 简化方案（AAC 挪到外部 muxer）已评估并因跨进程音视频时间轴同步成本高而**不采纳**，维持 exe 内 AAC。

## NVIDIA Video Codec SDK（独立第三方依赖，非 ffmpeg）
- 下载：https://developer.nvidia.com/video-codec-sdk/download （需 NVIDIA 开发者账号登录 + 接受许可）。最新为 **Video Codec SDK 13.0**（13.0.37 / 13.0.19）。
- 本质：SDK 只是 API 头文件 + 一个瘦加载桩 `nvEncodeAPI.lib`（运行时去调驱动里的 `nvEncodeAPI64.dll`）。**真正的编码器在 NVIDIA 驱动里**，不在 SDK。
- SDK 13.0 最低驱动要求 = **570.0**（Windows/Linux）。ffmpeg 8.1 用的 nv-codec-headers 对应 SDK 13.0.19；用户驱动 571 ≥ 570 → **SDK 13.0 与 ffmpeg 8.1 / 驱动 571 完全对齐**。
- **关键工程要求**：exe 必须做运行时 API 版本协商（`NvEncodeAPIGetMaxSupportedVersion` + `min(SDK版本, 驱动最大版本)` 作为 `apiVersion`），否则编译 SDK 13.0 会硬锁用户驱动 ≥ 570。协商后即便旧驱动（如 470+ 仅基础 H.264）也能跑基础编码。这是 `nvenc_encoder.cpp` 的实现点，工程师务必落实。
- NVIDIA SDK 目录布局：头文件在 `Interface/`（非 `include/`），lib 在 `Lib/x64/nvEncodeAPI.lib`。我们 CMake 期望 `include/nvEncodeAPI.h` + `Lib/x64/nvEncodeAPI.lib`，故需工程师调整 CMake 包含路径或把 `Interface/` 复制到 `include/`。
- 用户已把 BtbN shared-8.1 放到 cowatch/tem，ffmpeg 依赖已确认合格（见下节）。
- **2026-07-13 更新**：用户已下载 SDK 13.0.37 替换 13.1.15（驱动 571 兼容）。已完成目录结构调整：SDK 根下 `include/`（从 `Interface/` 拷入）、`Lib/x64/`（从 `Lib/win/x64/` 拷入）。ffmpeg 运行时 DLL（`avcodec-62.dll`/`avutil-60.dll`）已拷到 `electron/bin/`。前置自检全 ✅。待用户在 Developer Command Prompt 跑 build.ps1。

## 真机 build 依赖核查结论（2026-07-12 下午，用户已下载到 tem/）
- ffmpeg（BtbN `ffmpeg-n8.1-latest-win64-lgpl-shared-8.1`）：**合格**。`lib/` 内含真 MSVC 导入库 `avcodec.lib`(146KB)/`avutil.lib`(500KB)（不是 `.dll.a`），`include/` 含 libavcodec/libavutil 等头，`bin/` 含运行时 `avcodec-62.dll`/`avutil-60.dll`（无独立 MinGW 运行时 DLL，DLL 自带运行时）。`FFMPEG_ROOT` 直接指向该包根即可；运行期需把 `avcodec-62.dll`+`avutil-60.dll` 拷到 `electron/bin/`（与 exe 同目录），build.ps1 当前只拷 exe 不拷 DLL。
- NVIDIA SDK：**用户下成了 13.1.15 而非 13.0**——这是阻断项。NVIDIA 官方（论坛 TomNVIDIA, 2026-05-27）明确 **SDK 13.1 最低驱动 = 610.00**；用户机器是 **驱动 571 < 610 → 不兼容**（编译能过，运行时 `NvEncodeAPICreateInstance` 必挂）。必须二选一：① 改用 **SDK 13.0**（最低 570，与 571 对齐，原推荐）；② 保留 13.1.15 但把显卡驱动升到 ≥ 610。推荐①（不动驱动）。
- NVIDIA SDK 目录布局：头在 `Interface/nvEncodeAPI.h`、lib 在 `Lib/win/x64/nvencodeapi.lib`；build.ps1/CMakeLists 期望 `include/nvEncodeAPI.h` + `Lib/x64/nvencodeapi.lib`。修正法（不改代码）：在 SDK 根内 `mkdir include & copy Interface\* include\` + `mkdir Lib\x64 & copy Lib\win\x64\* Lib\x64\`（或建 junction）。13.0 同样适用。
- `nvenc_encoder.cpp:64` 硬编码 `sess.apiVersion = NVENCAPI_VERSION;` **无运行时协商**（`NvEncodeAPIGetMaxSupportedVersion` 缺失）。用 SDK 13.1 编 + 驱动 571 直接挂；换 13.0 后本机(571≥570)可跑，但老驱动终端用户仍会挂。发布前必须由工程师补协商（寇豆码）。
