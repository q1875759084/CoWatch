## 窗口录屏模式 - 对象窗口关闭行为分析

### 完成内容
- 深入分析了 `electron/handlers/recorder.ts` 中窗口录屏模式的完整代码
- 梳理了被录制窗口关闭时的行为链：gfxcapture 失去目标 → ffmpeg crash → handleFfmpegCrash 用相同 displayTitle 重启 3 次 → 全部失败 → push recorder:error
- 确认代码中无主动窗口状态检测机制（无定时器/事件监听被录制窗口）
- 确认 CoWatch 主窗口关闭时无 before-quit 钩子调用 stop()，ffmpeg 被强杀，尾片丢失
- 提出 3 种解决方案：
  - 方案A（推荐）：主动轮询 desktopCapturer 每 2s 检测窗口是否存在
  - 方案B（备选）：ffmpeg stderr 错误码识别，跳过重启直接 stop()
  - 方案C（长期）：Windows 原生 API SetWinEventHook 事件监听
- 分析报告已写入 `docs/窗口录屏-窗口关闭行为分析.md`

### 窗口哨兵原生 API 方案深入评估
- 评估了 SetWinEventHook 的复杂度、兼容性、bug 风险
- 结论：GitHub 上没有符合需求的现成 exe，需求太窄
- 项目已有模式：audio_capture.exe（独立 exe + stdout pipe），sentinel 应复用此模式
- 确认三种实现路径：koffi FFI / C++ addon / 独立 exe，推荐独立 exe（完美对齐项目模式）
- 独立 exe 进程隔离，线程安全天然解决，不受 Electron ABI 影响
