# 2026-07-21 集成规划：window_capture(OBS自编译) ↔ CoWatch

## 关键事实（真机编译完成后核对源码确认）
- `window_capture` 仓库已编译完成。薄壳 exe 在 `build-shell/RelWithDebInfo/window_capture.exe`，
  但**完整运行时在 `dist/`**（`dist/bin/64bit/`：exe+libobs+全部插件DLL+ffmpeg DLL+data+get-graphics-offsets64.exe）。
  `dist/` 即部署包，整包搬即可，不要手移 DLL。
- **模式已裁剪**：新 exe 只支持 `--mux-target file|null`（push 已废除，见 `config.h:11`）。
- **产出**：exe 内部用 OBS `ffmpeg_muxer` **直接写本地 HLS**（m3u8+ts），不再有外部 ffmpeg-mux 子进程。
  即录制+封装一体；上传仍由 CoWatch 负责，但边界从「管道收字节」变「监听本地 .ts 切片」。
- CLI 实测（`config.cpp::parse`）：只认 `--pid`（不认 `--hwnd/--title`）；`--out` 为 m3u8 路径或目录；
  READY JSON 含 `out` 字段（本地播放列表绝对路径），CoWatch 须读它定监听目录。

## 决策（用户 2026-07-21 确认）

3. **保留**：screen 模式 ffmpeg 链路（`ffmpeg.exe`/avcodec/avutil/swresample DLL、`audio_capture.exe`、

## 窗口选择契约核查（2026-07-21 续 — 另一 AI 质疑 + 主理人独立核实）
- **质疑成立**：之前集成文档 §2.2「CoWatch 传 `--pid` 给 exe」是**错契约**。独立核实确认：
  - `preload.ts:33-38` `recorder:start` 收 `windowId`(desktopCapturer sourceId) + `displayTitle`；`recorder/index.ts:234` sourceId 直接来自 `desktopCapturer.getSources()`（Win 上形如 `window:<HWND>[:suffix]`，含 HWND **非 PID**）。
  - `obs-studio/plugins/win-capture/window-capture.c`：`update_settings`(:211) 读 `window` 字符串 + `priority`，`ms_build_window_strings` 拆成 class/title/exe；每帧 tick(:630) 用 `ms_find_window_top_level(priority,class,title,exe)` **重解析 HWND**。**OBS 从不用 PID/HWND 做存储** → 我们 `--pid→EnumWindows 取首个可见窗口` 是画蛇添足且丢精度的自定义逻辑。
  - `window_sentinel.py:513` `find_target_window(title)` 哨兵本就按标题 EnumWindows 取 hwnd，且已有 `_get_window_pid/_get_window_class`（hwnd→三元组工具）→ CoWatch 完全具备从 HWND 反推 `title:class:exe` 的能力。
- **结论**：窗口选择契约必须重做，对齐 OBS 的 `window`(title:class:exe)+`priority` 模型；`--pid` 仅留作 documented-lossy 兜底。
- **主理人推荐契约（细化另一 AI 提案）**：
  1. exe 主契约 `--hwnd <十进制HWND>`：CoWatch 从 sourceId 解析 HWND 直传；exe 内用 GetWindowText/GetClassName/GetWindowThreadProcessId 反推 `title:class:exe` → 设 OBS `window` 属性。**最精确、零歧义（多进程游戏不丢窗），且仍 100% OBS 一致**（最终输入就是 window 串+priority，每 tick 重解析）。
  2. 备选/兜底 `--window "title:class:exe" --window-priority class|title|exe`（OBS 字符串原样直传，便于 sentinel/测试）。
  3. 删 exe 内 `resolve_pid_to_window` 的「首个可见窗口」启发式。
  4. **额外（另一 AI 未提）**：sentinel 也应从「按标题子串解析」改为吃 `--hwnd`，使 HWND 成为 capture+detect 单一事实源，消除标题同名歧义。
- **下一步**：建议先走**架构评审**（高见远出「窗口选择对齐 OBS」修订设计+影响面清单，含 integration.md §2.2/§6 错契约纠偏），用户确认后再由寇豆码改 exe(C++)+CoWatch TS(profiles/recording/sentinel)，严过关回归。efficiency 可选直接实现。

## 更正：实时上传并非「增强」（2026-07-21 深夜 — 用户质疑后核实）

- 源码坐实：
  - **切片实时上传本就存在**：`recorder/index.ts:614-635` chokidar 监听 `tmpDir` 匹配 `_opt.ts` → `enqueueUpload`（录制中逐片实时上传）。

- **结论**：本次集成只改 chokidar 文件名匹配 `_opt.ts`→`.ts`，**实时上传能力既有的、完整保留**；playlist 仍后端重建，客户端不传。所谓「实时上传 index.m3u8 属增强」是误导——准确说只有「录制中观众实时看（LIVE 直播边缘）」才需另推 playlist，那是独立产品增强，不阻塞本次集成。
