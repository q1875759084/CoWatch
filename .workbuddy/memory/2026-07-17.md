## 方案2a 真机回归：file 模式 CPU 100% + encode_fps 0.7 + ffmpeg "Timestamps are unset"

用户真机跑 file 模式（本地预览）报新回归：
- STATS：`capture_fps 13.9→5.1`、`encode_fps 0.7→2.6`、`cpu_pct 100`、`out_bps ~15kbps`
- ffmpeg：`Timestamps are unset` / `first pts and dts value must be set` → `Conversion failed!`，seg000.ts 仅 72KiB(1 帧)后失败。

### 根因判定（已读源码）
- **主因是编码管线卡死（Symptom A）**。主循环 `main.cpp:690-726` 每 tick `Sleep(33ms)`，不可能自旋到 100% CPU；`pipe_output.cpp:17-35 writeFd` 遇 EPIPE 直接 break，无自旋；stats.cpp:86-105 的 cpu_pct 算法正确（单核满占用=100）。
- `encode_fps 0.7` = 每 ~1.4s 才成功 1 帧，而 `cpu_pct 100` → N 卡驱动在 `nvEncLockBitstream(doNotWait=0)`（`nvenc_encoder.cpp:202-209`）里忙等编码完成，说明 encode session 处于"几乎不完成"的病态。
- **最强嫌疑**：`encodeTex`（`main.cpp:581` createEncodeTexture，BindFlags=RENDER_TARGET|SHADER_RESOURCE）同时被 (a) `BgraToNv12::convert` 当渲染目标写 NV12（`main.cpp:261-315`），(b) NVENC 注册为输入纹理（`nvenc_encoder.cpp:151-162`）。Draw 之后仅 `OMSetRenderTargets(0,nullptr,nullptr)` 解绑，**无显式 Flush / 资源状态转换**就让 NVENC Map 同一纹理 → 状态冲突使 NVENC 卡住/偶发成功（即 0.7fps）。
- **Symptom B（时间戳）是下游症状**：因为上游几乎不产可用 H.264（0.7fps / 15kbps），ffmpeg 拿到的是破碎稀疏流，`-r 30 -fflags +genpts`（`mux_target.cpp:109-115`）无法建立 PTS → mpegts muxer 拒首包。待 A 修好、30fps 真帧流入后大概率自愈；仍建议做参数加固。

### 处置（待用户确认后派 engineer+QA）
- engineer：① 编码前对 encodeTex 显式 `m_ctx->Flush()` 或改用独立 staging NV12 纹理给 NVENC（OBS 稳健做法）；② `doNotWait` 改 1 + 有界轮询/超时，避免卡死永久占满 CPU；③ 编码失败打印 NVENC 错误码；④ ffmpeg 参数加固（保持 `-r <fps>`+genpts，可选加 `-start_at_zero`/必要时改 re-encode 兜底）。
- QA：静态复核 + 真机回归（确认 encode_fps 回到 ~30、cpu_pct 回落、seg000.ts 非 0、index.m3u8 末尾有 ENDLIST）。

## 代码评审修复轮（temp/7.17ai.md 另名 AI 评审，2026-07-17 晚）
- 主理人逐条对照真实代码 + OBS 本地源码核实该评审。判定：**N1/问题1/N2/问题5/问题4 共 5 项真实须修；N3 是误报（其"修复"本身引入 D3D11 回归）已回退；窗口缩放(问题2)暂缓；窗口移动已支持无需改；问题7-14 冗余暂缓。**
- **已修 5 项**：
  - N1（nvenc_encoder.cpp tryLockPacket）：kBusy 分支不再 unmap input，仅 kReady/kError 才 unmap（NVENC 异步编码期间 input 须保持 mapped，对齐 OBS nvenc.c:1083）。
  - 问题1（winrt_capture.cpp）：拆 `ensureLatestTextureLocked`（内部不加锁），`onFrameArrived` 持锁改调之，消除 std::mutex 不可重入自死锁（潜在 P0）。
  - N2（main.cpp renderLoop）：每 tick 都产帧（无新帧则重编码上一帧，非重发旧 NAL）→ 恒定目标 fps，消除 VFR 与 muxer `-r` CFR 冲突导致的播放倍速。
  - 问题5（nvenc_encoder.cpp）：bitstream `bs.size=0` 让 SDK 13 自动 sizing（原 width*height*4 对 IDR 偏小）。
  - 问题4（main.cpp）：`rcLookahead` 默认 20→0（LOW_LATENCY 默认关 lookahead；gated 启用逻辑保留，`--rc-lookahead` 仍可覆盖）。
- **N3 回退（关键）**：原建议"convertLatestInto 锁内仅拷贝、释放锁后 convert"。但本设计 `BgraToNv12::m_ctx`≡`winrt::m_context`≡`main::immediateCtx` 是**同一 D3D11 立即上下文**（单设备 GetImmediateContext 单例），立即上下文非线程安全，N3 使渲染线程 convert 与回调 CopyResource 并发操作同一上下文→未定义行为。OBS 的 `obs_enter_graphics` 是图形锁、渲染线程持它做完整 convert（非释放），该 AI 误将"纹理锁"当"图形锁"。回退 convertLatestInto 到 pre-N3 持锁做完整 fn，删 m_scratchBgra。
