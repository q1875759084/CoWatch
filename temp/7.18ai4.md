## 二、新发现的问题

### 🔴 P0-1：`winrt::init_apartment()` 与 `DQTAT_COM_STA` 公寓类型矛盾

[main.cpp:493](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/main.cpp#L493)：
```cpp
winrt::init_apartment();
```

`winrt::init_apartment()` 不带参数时**默认初始化为 MTA**（`RO_INIT_MULTITHREADED`，见 C++/WinRT 源码 `inline void init_apartment(apartment_type type = apartment_type::multi_threaded)`）。

而 [winrt_capture.cpp:78](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/winrt_capture.cpp#L78) 用 `DQTAT_COM_STA` 创建 dispatcher。根据 Microsoft 文档，`CreateDispatcherQueueController(DQTAT_COM_STA)` **要求当前线程已初始化为 STA**，否则调用失败。

**后果**：在严格的 MTA 线程上，`CreateDispatcherQueueController` 会返回 `0x80010119` (RPC_E_WRONG_THREAD) 或类似错误，`wgc.init()` 返回 false，exe 退出码 1。WGC 会话根本建不起来。

> 注：Windows 10 1709+ 的 `RO_INIT_MULTITHREADED` 在某些版本会静默降级为 ASTA（与 STA 兼容），所以可能在部分机器上能跑、部分机器上挂。这是最危险的不确定性。

**修复**（对齐 OBS `CoInitializeEx(NULL, COINIT_APARTMENTTHREADED)`）：
```cpp
winrt::init_apartment(winrt::apartment_type::single_threaded);
```

### 🟠 P1-1：`drainEncoded` 的 gate 门控是凭空实现，且阻塞 lock 无超时

[main.cpp:890-923](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/main.cpp#L890)：
```cpp
auto drainEncoded = [&]() {
  const int gate = static_cast<int>(ep.bf) + 1;  // bf=2 → gate=3
  while (static_cast<int>(inFlight.size()) > gate) {  // size > 3 才 drain
    ...
    NvencEncoder::LockResult r = nvenc.tryLockPacket(...);  // 阻塞，无超时
    ...
  }
};
```

**两个问题**：

1. **gate 门控是非阻塞时代的遗物**。旧代码用非阻塞 `tryLockPacket` + kBusy 退让，gate 门控用于避免在 B 帧重排窗口未填满时 lock。现在 `tryLockPacket` 已改阻塞（[nvenc_encoder.cpp:295](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/nvenc_encoder.cpp#L295)），gate 门控多余。OBS 的模型是"submit 一帧 + 非阻塞 tryGetBitstream，busy 则跳过"，没有 gate 门控。

   **副作用**：steady state 下 `inFlight` 始终保持 `gate=3` 帧不输出，直到收尾 EOS drain 才排空。如果录制中途 WGC 帧率抖动（游戏卡顿），`inFlight` 可能 < gate，drain 完全停工，输出停滞。

2. **主循环内的阻塞 lock 无超时**。`tryLockPacket` 是阻塞的，如果 NVENC 内部异常（驱动 bug、设备丢失未捕获），`drainEncoded` 会**永久阻塞主循环**，导致 stdin 的 'q'、Ctrl+C 都无法退出（g_quit 检查在主循环顶部，进不去）。收尾的 EOS drain 有 30s 预算，但主循环里的 `drainEncoded` 没有。

**建议**：两条路二选一——

- **路 A（更对齐 OBS）**：把 `tryLockPacket` 改回非阻塞（`doNotWait=true`），恢复 `kBusy` 返回值，`drainEncoded` 遇 kBusy 则 break 不当错误。gate 门控可保留也可删。这是 OBS 的实际模型。
- **路 B（保留阻塞 + 加超时）**：阻塞 lock 加 100ms 超时（用 `WaitForSingleObject` 或轮询 `doNotWait` + `Sleep`），超时则 break 主循环 drain，下一轮再试。gate 门控保留。

> 我推荐**路 A**：当前代码的注释声称"对齐 OBS nvenc.c:1110 阻塞 lock"，但 OBS 的 `nvenc.c:1110` 实际用的是**非阻塞 + NEED_MORE_INPUT 跳过**模型，不是纯阻塞。阻塞 lock 是这一轮重构的"过度修正"——把旧的 kBusy 退让 bug 修正为阻塞，但引入了主循环挂死风险。OBS 的真模型是非阻塞 + 跨帧延迟获取。

### 🟠 P1-2：`PeekMessage` 用 `if` 而非 `while`，WGC 回调会堆积

[main.cpp:940](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/main.cpp#L940)：
```cpp
if (PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE)) {
  TranslateMessage(&msg);
  DispatchMessage(&msg);
}
```

OBS [obs-video.c:1107-1112](file:///c:/Users/绝绝子/Desktop/Co/obs-studio/libobs/obs-video.c#L1107) 用 `while (PeekMessage(...))` **排空所有消息**。当前用 `if` 只取一条，WGC 高频回调（30-60fps）下消息队列会堆积，主循环节奏被打乱——每轮只处理一条消息，剩余消息积压到下一轮，导致 `drainEncoded` 和 `tryConsumeFrame` 的节拍不稳。

**修复**：
```cpp
while (PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE)) {
  TranslateMessage(&msg);
  DispatchMessage(&msg);
}
```

### 🟠 P1-3：`drainEncoded` 的 kError 分支在设备丢失时会丢失 inFlight 帧但不重置 consecutiveFail

[main.cpp:903-910](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/main.cpp#L903)：
```cpp
} else {  // kError
  if (device->GetDeviceRemovedReason() != S_OK) {
```

设备丢失时 `drainEncoded` 直接 return，但**没有清空整个 inFlight 队列**。下一轮主循环顶部 `GetDeviceRemovedReason() != S_OK` 触发 `rebuildDevice()`，`rebuildDevice` 调 `nvenc.destroy()`（经 lossRelease），NVENC encoder 被销毁。但 `inFlight` 队列里还残留 bf+1 个 Job，它们的 slot 指向已销毁的 NVENC registered ptr。重建后 `freeSlots` 被重新填充（[main.cpp:832-833](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/main.cpp#L832) 只在启动时填一次），`inFlight` 残留的 Job 不会被处理——slot 计数错乱，`freeSlots` 可能空或重复。

**修复**：`rebuildDevice` 开头清空 `inFlight` + 重填 `freeSlots`：
```cpp
auto rebuildDevice = [&]() {
  inFlight.clear();
  freeSlots.clear();
  for (int i = 0; i < static_cast<int>(encInputs.size()); ++i) freeSlots.push_back(i);
  consecutiveFail = 0;
  frameIndex = 0;  // 重置时间戳
  ...
};
```
