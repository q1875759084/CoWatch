\## 二、新发现的问题



\### 🟠 P1-新1：`m\_firstFrame` 在 init/destroy 不重置，设备丢失重建后首帧非 IDR



grep 确认 `m\_firstFrame` 只在 \[nvenc\_encoder.cpp:243-246](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/nvenc\_encoder.cpp#L243) 读/写：



```cpp

if (m\_firstFrame) {

&#x20; pic.encodePicFlags = NV\_ENC\_PIC\_FLAG\_FORCEIDR;

&#x20; m\_firstFrame = false;

}

```



但 \[init()](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/nvenc\_encoder.cpp#L69) 和 \[destroy()](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/nvenc\_encoder.cpp#L333) \*\*都不重置 `m\_firstFrame`\*\*。



\*\*后果\*\*：设备丢失重建路径 `rebuildDevice` → `lossRelease`(`destroy`) → `lossRebuild`(`init`) 后，`m\_firstFrame` 仍是 false（destroy 没重置，init 没重置）。重建后首帧不会 FORCEIDR。



\- NVENC 重建后 encoder 是全新的，内部状态干净，但首帧是否自动 IDR 取决于 NVENC 实现，不保证。

\- HLS 切片依赖 IDR 同步解码器。重建后若首帧非 IDR，播放器可能花屏直至下一个自然 IDR（gop=250 → 最长 8 秒）。

\- OBS 的 device\_loss\_rebuild 走完整 init 路径，会重置 firstFrame 等价状态。



\*\*修复\*\*（1 行）：`init()` 开头加：

```cpp

if (m\_inited) return true;

m\_firstFrame = true;   // ← 重建后首帧强制 IDR，保证流可解码

m\_profile = profile;

```



\### 🟠 P1-新2：收尾 EOS drain 的 30s 预算对阻塞 lock 无效（与 P1-1 同源）



\[main.cpp:975-1005](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/main.cpp#L975) 收尾 drain：

```cpp

while (!allDrained \&\& budgetMs > 0) {

&#x20; for (size\_t i = 0; i < encInputs.size(); ++i) {

&#x20;   ...

&#x20;   ...

&#x20; }

&#x20; if (!allDrained \&\& !progress) {

&#x20;   Sleep(kYieldMs);

&#x20;   budgetMs -= kYieldMs;  // ← 永远到不了这里，因为上面阻塞
```

`tryLockPacket` 是阻塞调用（\[nvenc\_encoder.cpp:295](file:///c:/Users/绝绝子/Desktop/Co/CoWatch/electron/bin/capture-src/nvenc\_encoder.cpp#L295) `doNotWait=false`）。如果某 slot 的 bitstream 永远不 ready（NVENC 内部错误、驱动 bug），`tryLockPacket` \*\*永久阻塞\*\*，`Sleep` 和 `budgetMs -= ` 永远到不了。30s 预算是装饰性的。

这与 P1-1 是同一根本问题：\*\*阻塞 lock 没有超时机制\*\*。修了 P1-1（改非阻塞 + kBusy）这个就一起修了。

\## 五、关于"模仿 OBS"的现状



上一轮你指出"本次改动是模仿 OBS 自己实现，不是基于 OBS 减法"。本轮修复印证了这个判断：



\- \*\*P0-1 修复方式\*\*：注释写"对齐 OBS CoInitializeEx(STA)"，但实际用的是 `winrt::init\_apartment(single\_threaded)`——这是 C++/WinRT 封装，不是 OBS 的裸 `CoInitializeEx`。功能等价，但仍是"模仿"。

\- \*\*P1-新1 `m\_firstFrame` 不重置\*\*：OBS 的 `obs-nvenc` 用 `obs\_encoder` 抽象，encoder 重建时框架自动重置首帧状态；当前 exe 用裸 `NvencEncoder` 类，`m\_firstFrame` 是成员变量，destroy/init 不重置——这是"自己实现"才有的遗漏。

\- \*\*P1-1 阻塞 lock\*\*：注释声称"对齐 OBS nvenc.c:1110 阻塞 lock"，但 OBS 实际用非阻塞 + NEED\_MORE\_INPUT 跳过。注释与 OBS 实际行为不符——这是"模仿时抄错了"的典型。



\*\*结论\*\*：当前代码仍是"模仿 OBS 核心逻辑自己实现"，P0/P1 修复是"把模仿偏差往 OBS 真行为靠拢"。这是上一轮说的"路 B（模仿 + 纪律）"路径。能否长期稳定，取决于：

1\. 短期：P1-新1 + P1-1 修完后，真机验证能否覆盖所有边界

2\. 长期：是否要走路 A（链接 libobs）根治——这是上一轮讨论的开放问题，建议真机验证通过后再评估
