# CoWatch Windows 音频录制接入指南

> 本文档供 Windows 开发/测试环境使用，描述当前已完成的代码改动、待完成的步骤，以及验证方法。

---

## 当前状态（代码已完成）

`electron/handlers/recorder.ts` 已完成全部改动：

- **删除**了旧的 WASAPI/dshow 设备探测逻辑（`detectWasapiAvailable` / `testWasapiDevices` / `testDshowLoopbackDevices`）
- **新增**了 `getAudioCapturePath()` 函数，在 Windows 上寻找 `electron/bin/audio_capture.exe`
- **改写**了 `spawnFfmpeg`：若找到 `audio_capture.exe`，启动它并将其 stdout（原始 PCM）pipe 到 FFmpeg stdin 作为音频输入
- **新增**了 `audioCaptureProcess` 变量，在 `cleanup()` 和 `handleFfmpegCrash()` 中正确终止和重启该进程

**macOS 不受影响**：`getAudioCapturePath()` 在非 Windows 上直接返回 null，继续静音录制。

## 验证 audio_capture 能录到系统声音

在 Windows 上，**先播放一段音频**（视频、音乐等），然后执行：

```powershell
# 录制 5 秒系统声音，输出为 test.wav
.\electron\bin\audio_capture.exe --sample-rate 48000 --channels 2 --bit-depth 16 2>$null | `
  .\electron\bin\ffmpeg.exe -f s16le -ar 48000 -ac 2 -i pipe:0 -t 5 test.wav -y

# 播放验证（需要系统有默认播放器关联 .wav）
Start-Process test.wav
```

如果 `test.wav` 有声音，说明 WASAPI Loopback 工作正常。

## 核心改动逻辑说明（供 AI 参考上下文）

### 架构

```
audio_capture.exe (WASAPI Loopback)
        │ stdout（原始 PCM s16le）
        ▼
FFmpeg stdin (pipe:0) ── input 0: 音频
FFmpeg ddagrab filter ── input 1: 视频（整屏）
FFmpeg gfxcapture     ── input 1: 视频（窗口）
        │
        ▼
FFmpeg muxer → HLS 切片（seg*.ts + index.m3u8）→ 上传后端
```

### 关键代码位置

| 函数 | 文件 | 说明 |
|------|------|------|
| `getAudioCapturePath()` | `electron/handlers/recorder.ts` | 定位 audio_capture.exe，macOS 返回 null |
| `spawnFfmpeg()` | 同上 | 启动 audio_capture 并 pipe，构造 FFmpeg 参数 |
| `cleanup()` | 同上 | 停止录制时 kill audio_capture |
| `handleFfmpegCrash()` | 同上 | crash 重启时先 kill 旧 audio_capture，再调 spawnFfmpeg（内部会启动新的） |

### FFmpeg 参数说明

有 `audio_capture.exe` 时，FFmpeg 命令结构为：

```bash
ffmpeg \
  -f s16le -ar 48000 -ac 2 -i pipe:0 \           # input 0: 音频（来自 audio_capture pipe）
  -f lavfi -i "ddagrab=output_idx=0:framerate=30,hwdownload,format=bgra,scale=..." \  # input 1: 视频
  -af "aresample=async=1:min_hard_comp=0.100:first_pts=0" \  # 自动音画对齐（偏移 < 50ms）
  -map 0:a -map 1:v \                             # 显式流映射（lavfi 无音频流，必须显式 map）
  -c:v h264_nvenc ... \                           # 视频编码（GPU 硬编优先）
  -c:a aac -b:a 128k \                            # 音频编码
  -f hls -hls_time 10 ... output/index.m3u8       # HLS 输出
```

无 `audio_capture.exe` 时（兜底）：
```bash
ffmpeg \
  -f lavfi -i "ddagrab=..." \   # 仅视频输入
  -an \                          # 无音频
  ...
```

### 音画同步原理

- `audio_capture.exe` 和 FFmpeg 在**同一个 event loop tick** 内 spawn，启动时间差约 0~50ms
- PCM 数据通过内核 pipe 传入 FFmpeg，进入同一个 muxer 的时间线
- `-af aresample=async=1` 让 FFmpeg 自动拉伸/压缩音频流以匹配视频 PTS，消除启动偏移
- 实际音画偏移预期 < 50ms

## 常见问题排查

### audio_capture.exe 启动失败（code=2）

原因：未找到音频输出设备（No audio device found）

处理：
1. 检查 Windows 声音设置，确认有可用的输出设备且未禁用
2. 确认系统默认播放设备正常

### audio_capture.exe 启动失败（code=3）

原因：Access denied

处理：
1. 以管理员身份运行应用
2. 检查 Windows 隐私设置 > 麦克风（WASAPI loopback 有时归在此权限下）

### 录制有画面无声音

1. 检查 console 是否输出 `音频输入: audio_capture WASAPI Loopback → pipe:0`
2. 若输出 `音频输入: 无（静音录制）`，说明 `audio_capture.exe` 未找到，检查文件路径
3. 若 audio_capture 正常启动但无声，先用上面的独立验证命令测试是否能录到系统声音

### 音画明显不同步（> 200ms）

1. 检查系统负载是否过高（CPU 满载会影响进程调度）
2. `aresample=async=1` 已经自动修正偏移，若仍然明显，可调整 `--chunk-duration` 从 0.1 减小到 0.05

### ffmpeg 报错 `pipe:0: Invalid data found when processing input`

原因：audio_capture 还没来得及输出数据，FFmpeg 就开始读 pipe 了

处理：此错误通常是启动瞬间的短暂现象，`aresample=async=1` 会自动处理音频开头的缺失帧，正常情况下不影响录制结果。若持续报错，检查 audio_capture 是否正常运行。

## 打包发布注意事项

`electron-builder.yml` 已配置：

```yaml
win:
  extraResources:
    - from: "electron/bin/"
      to: "bin/"
      filter:
        - "**/*"
```

`electron/bin/` 目录下的所有文件（包括 `audio_capture.exe`）会被自动打包到安装包的 `resources/bin/` 目录，`getAudioCapturePath()` 在 packaged 模式下也能正确找到它。

**无需修改 electron-builder.yml**。

对，理解完全正确。
plain text
Apply
audio_capture.exe进程          FFmpeg进程
─────────────────              ─────────────────
WASAPI Loopback采集            ddagrab采集显示器画面
    │                               │
    │ stdout (原始PCM)              │ (内部filter)
    │                               │
    └──────── pipe ────────────────▶ stdin (pipe:0)
                                    │
                            两路流在FFmpeg内部合并
                                    │
                            HLS切片输出 → 上传
两个独立进程，通过操作系统 pipe 连接：
audio_capture.exe 负责：调用 Windows WASAPI Loopback API，把系统正在播放的声音采集成原始 PCM，往 stdout 写
FFmpeg 负责：从 stdin 读 PCM 作为音频流，同时用 ddagrab filter 抓视频帧，在内部 muxer 里把两路流合并编码成 HLS 切片
为什么用 pipe 而不是临时文件？
pipe 是流式的，音频数据边采集边传给 FFmpeg，不需要等录制结束再合并
磁盘上只写最终的 HLS 切片，没有中间的 wav 临时文件
FFmpeg 内部统一管理时间线（PTS），音画对齐在 muxer 层完成
唯一需要注意的是：pipe:0 的 PCM 没有文件头，FFmpeg 不知道格式，所以必须在命令行显式告诉它格式参数 -f s16le -ar 48000 -ac 2，这正是代码里 audioInputArgs 的作用。
