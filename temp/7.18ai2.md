\## 凭空实现的部分



\### 1. dispatcher 类型 + 双重尝试



| | OBS | 当前 |

|---|---|---|

| threadType | DQTYPE\_THREAD\_CURRENT | DQTYPE\_THREAD\_DEDICATED |

| aptType | DQTAT\_COM\_STA（一步） | DQTAT\_COM\_NONE→STA（两步兜底） |

| 图形线程 | main 线程兼 dispatcher（有 PeekMessage 循环） | 专用线程兼 dispatcher（自泵） |



\*\*凭空原因\*\*：当前 exe 的 main 线程不做图形工作（只是协调者），所以不能用 CURRENT，被迫用 DEDICATED。而 DEDICATED + NONE→STA 双重尝试是调试期遗留。



\### 2. m\_onFrame 回调注入机制



| | OBS | 当前 |

|---|---|---|

| 回调通知方式 | `texture\_written = true` 标志 + `winrt\_capture\_render` 函数（渲染时检查标志） | `m\_onFrame` std::function 回调注入 + `m\_frameCbReady` 原子屏障 |

| init 同步 | dispatcher 线程内同步初始化 | std::promise/future 跨线程同步 |

| WGC 初始化 | 图形线程主循环里直接调 | TryEnqueue 投递到 dispatcher 线程 |



\*\*凭空原因\*\*：OBS 有主循环（output\_frames）在图形线程主动调用 render，所以用标志位即可。当前 exe 没有主循环，只能用回调注入让 onFrameArrived 主动推帧给转换逻辑。



\### 3. BgraToNv12 转换类



| | OBS | 当前 |

|---|---|---|

| 转换方式 | libobs graphics 层 `gs\_draw\_sprite` + CPU 矩阵（video-matrices.c） | 自定义 HLSL 着色器 + 双 plane RTV（luma pass + chroma pass） |

| 着色器 | 不需要（gs\_draw\_sprite 内部处理） | 手写 VS + PS\_Luma + PS\_Chroma + D3DCompile 运行时编译 |



\*\*凭空原因\*\*：OBS 依赖 libobs graphics 层，当前 exe 不链 libobs，必须用原生 D3D11 替代。这部分\*\*有一定必要性\*\*（不链 libobs 就得自己写），但实现方式（双 plane RTV + 运行时编译 HLSL）是自行设计的，OBS 没有这个代码。



\### 4. 编码线程 + SPSC + 非阻塞 lock



| | OBS | 当前 |

|---|---|---|

| 编码位置 | 图形线程同步（output\_frames 里调 nvenc\_encode） | 独立编码线程 |

| 帧交接 | 无（同线程同步） | StagingPool ring + FrameQueue SPSC |

| LockBitstream | 阻塞（doNotWait=0） | 非阻塞（doNotWait=1）+ kBusy 退让重试 |



\*\*凭空原因\*\*：这是整个链条的关键。当前 exe 把转换塞进 onFrameArrived 回调（因为没有主循环），如果编码也在回调里，整个 CopyResource→convert→flush→encode→lock 链路会阻塞 WGC 递帧。被迫把编码分离到独立线程，衍生出 SPSC + 非阻塞 lock + kBusy 退让。OBS 不需要这些，因为 on\_frame\_arrived 只 CopyResource，编码在 output\_frames 主循环里，两者分离天然无阻塞。



\### 5. OutputTarget 三态 + stderr 透传



| | OBS | 当前 |

|---|---|---|

| 输出抽象 | obs\_output 体系（obs-ffmpeg-mux.c / obs-ffmpeg-hls-mux.c） | OutputTarget 基类 + Push/File/Null 三态 |

| stderr 透传 | 无（OBS 自己就是 ffmpeg） | stderrPumpThread 泵线程 |

| ffmpeg 参数 | obs-ffmpeg-hls-mux.c 配置 | 对齐但自行拼装 |



\*\*凭空原因\*\*：OBS 自己就是编码器+muxer（链 libavformat），不需要 spawn ffmpeg。当前 exe 不链 libavformat，必须 spawn ffmpeg.exe 做封装，衍生出 OutputTarget 抽象 + 管道管理 + stderr 透传。



\## 凭空实现的根源链条



不是孤立的凭空设计，而是一条因果链：



```

main 不做图形工作（只是协调者）

&#x20; → 不能用 DQTYPE\_THREAD\_CURRENT，被迫 DEDICATED

&#x20; → 没有主循环（PeekMessage + output\_frames）

&#x20; → 转换塞进 onFrameArrived 回调（m\_onFrame 注入）

&#x20; → 回调内 convert+encode 会阻塞 WGC 递帧

&#x20; → 编码分离到独立线程

&#x20; → 衍生 SPSC + 非阻塞 lock + kBusy 退让

```



OBS 的根是 `DQTYPE\_THREAD\_CURRENT`：main 线程 = 图形线程 = dispatcher 线程，有 PeekMessage 主循环，on\_frame\_arrived 只 CopyResource，渲染和编码在主循环同步执行。整条链简洁，无锁、无队列、无回调注入。



当前 exe 在根上偏离了（DEDICATED 而非 CURRENT），后续每一层都在弥补这个偏离带来的问题，每一层都是凭空实现。



\## 客观评价



并非所有凭空实现都是"错误"：



\- \*\*BgraToNv12\*\*：不链 libobs 的必然结果，有一定必要性

\- \*\*OutputTarget\*\*：不链 libavformat 的必然结果，有一定必要性

\- \*\*编码线程分离\*\*：有合理性（避免 NVENC 阻塞 WGC 回调），但 OBS 用更简单的同步编码解决



但以下凭空实现是\*\*不必要的偏离\*\*：



\- DQTAT\_COM\_NONE→STA 双重尝试（OBS 直接 STA）

\- m\_onFrame 回调注入（OBS 用 texture\_written 标志）

\- std::promise/future 跨线程同步（OBS 同线程同步）

\- tryLockPacket 非阻塞 + kBusy 退让（OBS 阻塞 lock）



这些偏离不是因为"不链 libobs"的必然结果，而是线程编排选择不同衍生的。\*\*如果要真正对齐 OBS\*\*，根上的修法是：main 线程变成图形线程（加 PeekMessage 主循环），用 DQTYPE\_THREAD\_CURRENT，onFrameArrived 只 CopyResource + texture\_written，主循环里做 convert + 同步编码。这样编码线程、SPSC、非阻塞 lock、回调注入全部可以删掉。



当前回滚已经消除了之前 9 个补丁问题，架构方向正确，但实现层面仍有约 40% 是凭空设计（主要在线程编排和帧交接机制上）。这些凭空设计目前能工作，但每一处都是潜在的 bug 来源。
