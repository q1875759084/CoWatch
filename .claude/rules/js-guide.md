# JavaScript 通用代码生成指南

JavaScript（泛指 JS、TS、JSX、TSX 等都应遵循的）代码生成应遵循以下规范。

## 组件、模块、函数设计原则

- 组件不超过 300 行代码，超出时拆分子组件
- 函数入参数量不要超过 4 个，可通过 "key-value 对象字面量" 方式传参减少入参

## TS 开发规范

- 项目开启 `strict` 模式，**禁止使用 `any`**，用 `unknown` + 类型守卫代替
- 避免使用 @ts-ignore，所有 TypeScript 类型错误必须通过正确定义类型或修正代码逻辑解决
- TypeScript 的公共类型定义需要放到 `types` 目录以避免重复定义
- API 响应类型用泛型约束 `ApiResponse<T>`，定义在 `src/types/api.ts`

## 编码规范

- 避免嵌套三元，提升代码可读性
- **import 顺序**：第三方库 → 本包内跨目录（`@/`）→ 相对路径；组间空一行，同组内按字母排序

## 模块副作用

- 模块顶层**禁止执行副作用**（禁止顶层 console 调用、网络请求、DOM 操作）
- 有副作用的逻辑必须封装在函数、Hook 或生命周期内，不得在 import 阶段触发

## utils 函数规范

- `utils/` 下的函数必须是**纯函数**（相同输入相同输出，无副作用）
- 有副作用的逻辑（如请求、状态读写、副作用触发）放 `hooks/` 或 `services/`，不放 `utils/`

## 代码健壮性要求

- 类型转换时必须设置默认值，如 `Number(a) || 0` 或 `String(a ?? '')` 以防出现不符合预期的结果
- 网络请求和接口异常处理函数封装在 `api` 目录下，使用已封装的 `request`（`src/utils/request.ts`）调用业务接口；以下两类场景例外（需在注释中说明原因）：OSS 预签名直传用原生 XHR（不能带自定义 Authorization 头）、后端返回 Blob 时用原生 `axios.get`（业务拦截器会误判）
- 所有异步操作必须有 `try/catch`，**不允许静默失败**
- 用户可见的错误统一用 `message.error()` 展示，兜底写法：`message.error((error as Error).message || '操作失败')`；**禁止直接传 error 对象**（会渲染为 `[object Object]`）
- 网络错误、权限错误、业务错误分类处理；401 由 `request` 拦截器自动刷新 Token 或跳转登录页，**不要再额外处理**

## 样式管理

- 颜色、字体等通用样式应使用变量定义在全局样式文件中

## 常量管理

- 常量在 `constants` 目录下统一维护
- 需要抽取常量的：需要在项目中保持一致、具有特殊业务语义的字符串枚举值和数字，避免魔法数字
- 不需要抽取成常量的：UI 上的文本，用户提示文案

<example>

```ts
// constants/index.ts
export const USER_ROLES = {
  ADMIN: 'admin',
  USER: 'user',
  GUEST: 'guest',
}
export const ORDER_STATUS = { PROCESSING: '1', SUCCESS: '2', FAILURE: '3' }
```

</example>

## 目录规范

- 文件名：组件用 PascalCase，工具函数用 camelCase
- 每个模块的 `index.ts` 只做导出，不写业务逻辑
- 私有组件放在页面目录的 `components/` 下，不向外暴露

## 优先使用真实数据源

- **严禁**在代码中直接写入任何模拟数据（mock data），包括但不限于：示例用户信息、测试数据数组、假的API响应数据、占位符数据
- 优先使用真实的数据源，只有当用户明确要求添加 mock 数据用于演示或测试时，才可以添加

## 代码生成前置要求

当需求涉及**新建文件超过 2 个**或**新增功能模块/新页面**时：
1. 必须先输出文件拆解计划（文件名、预估行数、依赖关系）
2. 输出完拆解计划后，**提示用户使用 `/code-gen` 指令启动生成流程**，不要自行继续生成
   > 示例提示语：「以上是本次任务的文件拆解计划，请使用 `/code-gen` 指令开始逐文件生成，以确保每个文件完成后做即时质量校验。」
3. 未收到 `/code-gen` 指令时，**不得自行开始生成任何文件**

以下场景**不受此限制**，可直接生成：
- 修改已有文件（bug修复、字段调整、样式改动）
- 新建文件数量 ≤ 2 个的小改动
